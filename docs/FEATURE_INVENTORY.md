# SiegePlugin Feature Inventory

Generated by a full-codebase audit, 2026-08-31. Covers `src/main/java` (155 classes,
~16,500 lines across 20 packages), `src/main/resources/{config.yml,maps.yml,plugin.yml}`,
and a comparison against every planning document in the repository and in
`~/Downloads/MAIN_PLAN.md`. See `CLAUDE_DISCREPANCY_REPORT.md` for defects and
unapproved-scope findings; this document only inventories what exists and why.

**Baseline:** `mvn clean test` — 273 tests, 0 failures, 0 errors, 0 skipped, clean build.
(The `target/` directory on disk before this audit held 79 stale Surefire XML reports
for only 67 real test classes — leftovers from deleted test files. A clean rebuild is
the only trustworthy source; do not read `target/surefire-reports` without rebuilding
first.)

**Doc precedence used to judge "authorizing document":** `AGENTS.md` + `memory/*.md`
(newest) > `SiegePlugin 1.1 Expansion.md` > `Stage_4.4_Agent_Build_Brief.md` >
`Stage_4.4_Implementation_Plan.md` > `~/Downloads/MAIN_PLAN.md` (oldest).

## System map

```
SiegePlugin.onEnable()
  -> saveDefaultConfig / saveResource(maps.yml)
  -> RuntimeKitOverrides, RuntimeMapOverrides applied
  -> TownyAdapter.provisionSpectatorTown()
  -> validateStartup()  [fail loud -> disablePlugin, RETURN]
  -> TownyAdapter, PotionStorageService, TeamAssignmentService,
     TeamDisplayService, SidebarService
  -> ActiveRoundProvider, RoundRoster, ActiveCombatEligibility (RoundActivityStatus)
  -> CaptureService (bootstrap-only banner/settings from config.yml)
  -> CombatTagAdapter (hard dependency), TeamSwitchService
  -> initializePlayerStateTransitions()  [constructs SiegeDatabase, KitService,
     KitEditorListener, PlayerStateTransitionService]
  -> ScoringService, MinecartCooldownService, CurrencyService
  -> initializeRoundServices()  [RotationCoordinator + all its ports]
  -> registerCommands(), registerListeners()
  -> start every scheduled service; RotationCoordinator.start() (async DB hydration)
```

Once `RotationCoordinator` publishes its first `ActiveRoundContext`, gameplay services
stop reading `config.yml`'s boot-time capture/spawn values and instead read the
published context; `rebindRoundServices()` (SiegePlugin.java:634) re-runs this binding
on every round activation.
