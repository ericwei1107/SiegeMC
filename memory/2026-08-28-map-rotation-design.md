# Design: Clean-Copy Map Rotation

Generated by office-hours on 2026-08-28  
Status: IMPLEMENTED AND HARDENED — live multiplayer acceptance pending
Mode: Builder

## Problem Statement

SiegePlugin is currently bound to one persistent `siegeworld` and an eternal score record. The community server needs finite rounds: a team reaches a configurable score limit, players see a winner announcement and lobby countdown, a newly revealed map begins at 0–0, and map damage never leaks into the next round.

## What Makes This Cool

The round ending is a ceremony rather than a loading failure: the winner is visible, players regroup in the lobby, the next map is revealed during a countdown, and everyone enters a clean battlefield together. The original map templates stay pristine forever.

## Premises

1. Map templates are immutable source worlds. A round runs only in a generated active copy, which is unloaded without saving and deleted after use.
2. Terrain from Sieges is reused, but every map is given a SiegePlugin manifest for Red/Blue spawns, capture banner, boundary, lobby handoff, and optional potion supplies. SiegePlugin retains its own kits and banner-control game mode.
3. Score-limit rotation is transactional. No score reset/new match occurs until a target map has copied, loaded, and validated successfully.
4. A failed rotation keeps the completed winner/score archive exactly once and leaves players safely in lobby recovery; it never reruns or double-awards the old match.
5. Map and kit voting remain later features. Kill, damage, banner, and weighted Overall MVP presentation are implemented in the winner ceremony.
6. The map owner has authorized reuse. Keep provenance/attribution documentation with the imported assets before publishing the open-source distribution.

## Reference: How Sieges Rotates

Sieges uses `FileMapLoader`: it copies a configured source world folder into `<template>_active_<number>`, excluding `session.lock` and `uid.dat`; loads that folder through Bukkit; disables autosave and applies match game rules; and later unloads without saving then recursively deletes only the active folder. `GameManager` shuffles its map queue, preloads the next map, delays the new game, and unloads the prior active copy after players leave.

SiegePlugin borrows the clean-copy idea, not the legacy implementation details: it will not kick players, recurse-delete broadly, or let score reset race a map load.

## Approaches Considered

### A. Reuse one live arena world

- Effort: S; Risk: High
- Reuse the existing snapshot system to import/reset maps into `siegeworld`.
- Rejected: this is not truly clean-copy rotation and exposes the active round to failed imports.

### B. SiegePlugin transaction with a Multiverse adapter

- Effort: L; Risk: Medium
- SiegePlugin controls the state machine while Multiverse loads/unloads copied worlds.
- Rejected: Multiverse adds a second lifecycle owner without solving transactional score/player safety.

### C. SiegePlugin-owned native Bukkit/Paper clean-copy loader — selected

- Effort: M; Risk: Low
- Copy template folders asynchronously, create/unload worlds through Bukkit/Paper on the main thread, and delete only generated active copies.
- Selected: closest to the proven Sieges workflow with one clear owner for match state.

## Recommended Approach

Approach C. It keeps the plugin responsible for the only decisions that matter to players—when a round is complete, where they go, when the next round begins, and when its scores become active—while using the proven template-copy lifecycle from Sieges.

## Rotation State Machine

`BOOTSTRAPPING → ACTIVE → COMPLETING → INTERMISSION → ACTIVATING → ACTIVE`, with failed preparation entering `RECOVERY`.

1. **ACTIVE:** durable scoring runs; a score-limit detector observes the post-write match score.
2. **COMPLETING:** one idempotent transition token freezes scoring/capture rewards, closes the winner record, and cancels capture sessions.
3. **INTERMISSION:** announce winner, final score, MVPs, and revealed candidate with a clickable lobby button; preserve the durable queue and force it to lobby after 40 seconds while preparing a clean copy.
4. **ACTIVATING:** publish the prepared map only after durable match creation, service rebinding, Towny-balanced roster application, fresh kits, and roster persistence succeed.
5. **Cleanup:** after no player remains, unload the prior active world without saving and delete only that generated folder.
6. **RECOVERY:** after selected, every other enabled map, and a clean previous-map fallback fail, leave players in the lobby with no new match until an admin retry succeeds.

If preparation fails, enter a visible lobby-recovery state; retain the completed match and offer a validated fallback/retry path. Do not create the new match or reopen scoring.

## Required Refactors

- Replace the eternal `MatchDefinition.eternalForWorld(...)` model with a distinct match record per activated round.
- Make `CaptureService`, team spawns, arena boundary/reset, minecart cleanup/protection, sidebar world/map context, and potion-supply location resolution bindable to an active map rather than boot-time `siegeworld` config.
- Remove the scheduled in-place reset and manual snapshot workflow; clean-copy rotation is the only normal reset boundary.
- Add a map manifest/validator and a runtime world loader abstraction; map manifest must be validated before a template enters rotation.
- Trigger rollover only after the winning score has persisted; ensure repeated score callbacks cannot create two rotations.

## Resolved Decisions

- Winning score defaults to 10,000 globally and preserves award overshoot.
- Intermission force is 40 seconds; fallback tries the revealed selection, every other enabled map once, then a fresh previous-map copy.
- The five maps' exact SiegePlugin capture/spawn/boundary locations, and whether their current map assets include all expected clean template data.
- Towny towns are internal team containers only; online queued fighters are shuffled/balanced within one at activation.
- Attribution file/location for the borrowed map assets.

## Correctness Hardening (2026-08-29)

A review pass found the lifecycle buildable but effectively untested and open to
several release-blocking failures. The following are now part of the design:

- **Attempt tokens.** Every preparation and activation runs under a token. A
  retry, shutdown, or recovery invalidates earlier tokens; a completion arriving
  under a stale token may only delete the world copy it created. This is what
  stops a slow copy from activating over a newer decision.
- **Compare-and-set lifecycle writes.** `rotation_state` carries a `revision`.
  Nothing — a phase change, queue entry, roster, abort, or publication — is acted
  on until its write lands. The winning score transaction must move rotation
  state to `COMPLETING` in exactly one row or the whole award, ledger entry,
  final statistics, winner, and status roll back.
- **The durable roster, not Towny, is authoritative.** `match_roster` carries
  `PLANNED`/`BATTLEFIELD`/`LOBBY` presence. One shared `ActiveCombatEligibility`
  policy (active phase + active runtime world + battlefield presence + role)
  gates deaths, damage MVP, capture, shop delivery, potion access, placed
  blocks, and siege minecarts.
- **Two-stage map admission.** Static checks read the manifest and template;
  loaded-copy checks need a real copy (spawn footing, headroom, capture support,
  supply chests) and share the same code path as `/siege admin rotation validate`,
  whose validation copies are always unloaded.
- **No transitional legacy round.** First boot archives `eternal-1` and opens
  intermission; with no enabled map it enters lobby recovery instead.
- **Durable cleanup.** Generated copies are enrolled in `generated_world_cleanup`
  before any unload, retried with capped backoff, and resumed after a restart.
  Untracked `siege-active-*` folders are reported, never deleted.
- **One failure never strands the round.** A failed evacuation, Towny move, or
  teleport excludes only that player; a five-minute preparation timeout abandons
  a hung copy instead of holding everyone in the lobby.

## Remaining Release Gates

1. Migrate the live `config.yml`: `scoring.winning-score` added; `activity-cycle`, `cleanup.map-reset-interval-hours`, and `arena-reset` deleted. Startup now fails naming any that remain.
2. Populate coordinates/bounds and template folders for at least two enabled maps, following the commented schema in `maps.yml`.
3. Run `/siege admin rotation validate all` and correct every failure. Validation reloads `maps.yml` and checks template readability, bounds containment for both spawns and the whole capture radius, legal spawn heights, distinct team spawns, and registered potion supplies. Block-level spawn safety still cannot be proven before the copy loads — confirm it in the live run.
4. Complete the live acceptance flow with four fighters and one spectator, including a forced-lobby holdout, a deliberately failed individual launch, clean previous-map fallback, restart in ACTIVE/INTERMISSION/ACTIVATING, and recovery retry.
5. Verify potion supplies on both maps and confirm legacy world-name records remain inactive rather than being deleted; the startup log names them.
